SVG diagram conventions

Solid vs. dashed, currentColor, markers, and the aria-label rule — for docs and the blog.

01 — One example

Solid means built. Dashed accent means proposed.

The one convention every architecture diagram in this system uses to separate what exists from what's agreed-but-not-built. Never invent a third line style for a third state — collapse it into one of these two, or add a legend that explains it.

02 — Mechanics

How every inline SVG in this system is built

Color from tokens, via var()Fills, strokes, and text reference --mv-ink, --mv-accent, etc. — never a hard-coded hex
Text fills currentColorInherited from .diagram-frame svg { color: var(--mv-text); }
A legend whenever both line styles appearSolid vs. dashed only needs explaining the first time it shows up together
role="img" + a mechanism-describing aria-labelNot "a diagram of the CLI" — a sentence describing what it argues
Arrowheads via <marker>, filled currentColorUnique id per diagram on a page — marker ids are document-global
Sized by viewBox, wrapped in an overflow-x: auto frameNever lets a wide diagram break the page on mobile
03 — Where this differs from ASCII

SVG is for docs and the blog. ASCII is for the terminal.

The CLI never renders SVG — see diagrams/ascii-conventions.html for its box-drawing equivalent of "built vs. proposed" (a solid rule vs. no equivalent; the CLI doesn't currently diagram proposed state, since a shipped binary has nothing hypothetical to show).
